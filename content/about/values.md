# Values

These are the working principles I actually try to apply — not the ones that sound good in interviews.

---

**1. Systems thinking over isolated fixes**  
Content problems are usually platform problems. Platform problems are usually process problems. Fix the root, not the symptom.

**2. Clarity beats cleverness**  
Code that a future-me can read at 9am on a Monday is worth more than code that impresses nobody at 3am.

**3. The editorial perspective matters**  
I've been on the content side. I know what it's like to work inside a system someone else designed. That shapes how I build.

**4. Finish things**  
Shipped and imperfect beats polished and hypothetical. Iterate from there.

**5. Honest scoping over optimistic estimates**  
Requirements gathering is a skill, not a formality. I'd rather surface complexity early than apologise for it later.
