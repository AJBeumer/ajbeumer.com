# Content Rules

## Maintenance rule
Update this file and the relevant docs/ files whenever content authoring rules, the content model, or the rendering pipeline changes. Keeping this file current reduces repeated instruction in future AI sessions.

## Purpose
These rules apply when editing user-facing markdown content.

## Rules
- Keep writing concise and human
- Avoid generic corporate language
- Prefer concrete wording over vague claims
- Use TODO placeholders instead of invented facts
- Keep files scan-friendly for terminal reading
- Use short sections and clear headings

## Content model
Each markdown file should represent one terminal-readable unit.

Examples:
- `content/about/bio.md`
- `content/work/current-role.md`
- `content/skills/core-skills.md`

## Do not
- bury key facts in long paragraphs
- duplicate the same content across many files
- mix internal notes with public-facing content
